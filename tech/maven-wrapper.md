# Maven Wrapper (3.3.4, `only-script` type)

## 1. What it is

The Maven Wrapper is a small script (`mvnw`) checked into the repository. When you run it, it downloads the exact Maven version the project wants, unpacks it in your home folder, and starts it. The idea: nobody has to install Maven, and everybody builds with the same version.

## 2. Why this repository uses it

The reader of this repository needs only a JDK. `./mvnw` then gives the same Maven (3.9.16) on the author's Mac, in CI and in the Docker build.

## 3. Where it appears

| File | What it does with the technology |
| --- | --- |
| `mvnw` | the shell script that downloads and starts Maven |
| `mvnw.cmd` | the same for Windows |
| `.mvn/wrapper/maven-wrapper.properties` | which Maven to download |
| `.mvn/jvm.config` | JVM options for the JVM that runs Maven (opens JDK internals for the formatter) |
| `Makefile` | every Maven call is `./mvnw`, never `mvn` |
| `Dockerfile` | runs `./mvnw` inside the build stage |

## 4. How it works underneath

- First run: `mvnw` sees no Maven in `~/.m2/wrapper/dists/`, downloads the zip named in `distributionUrl` over HTTPS, unpacks it, and starts `bin/mvn` from it.
- Next runs: the folder exists, so `mvnw` starts Maven at once.
- `mvnw` is an ordinary executable file in git (mode 755). If the executable bit is lost, `./mvnw` says `Permission denied`.
- Because Maven's own JVM reads `.mvn/jvm.config`, the options in it apply to every Maven command in this folder.

## 5. Walkthrough of this repository's use

```properties
wrapperVersion=3.3.4
distributionType=only-script
distributionUrl=https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/3.9.16/apache-maven-3.9.16-bin.zip
```

This file tells the wrapper script what to download. `wrapperVersion=3.3.4` is the version of the wrapper itself. `distributionType=only-script` means the repository holds only the shell script (`mvnw`) and no helper jar; the script downloads Maven with `curl` or `wget` (or, if neither exists, compiles a tiny Java downloader). `distributionUrl` is the exact Maven 3.9.16 zip on Maven Central. The script unpacks it into `~/.m2/wrapper/dists/`, once.

```text
--add-exports jdk.compiler/com.sun.tools.javac.api=ALL-UNNAMED
--add-exports jdk.compiler/com.sun.tools.javac.file=ALL-UNNAMED
--add-exports jdk.compiler/com.sun.tools.javac.parser=ALL-UNNAMED
--add-exports jdk.compiler/com.sun.tools.javac.tree=ALL-UNNAMED
--add-exports jdk.compiler/com.sun.tools.javac.util=ALL-UNNAMED
--add-exports jdk.compiler/com.sun.tools.javac.code=ALL-UNNAMED
```

`.mvn/jvm.config` holds options that `mvnw` passes to the JVM that runs Maven itself. Each `--add-exports module/package=ALL-UNNAMED` line opens an internal package of the JDK's compiler module to all code on the class path. Google's code formatter (run by the Spotless plugin) reads Java source with the compiler's internal parser, and Java 25 blocks that access unless it is opened. Without these lines `make lint` fails with a reflection error.

```bash
#!/bin/sh
```

`mvnw` is a long Bourne-shell script (about 300 lines). Its job in order: find a Java (`JAVA_HOME` or `java` on the path), read `maven-wrapper.properties`, download and unpack the Maven distribution if `~/.m2/wrapper/dists/` does not have it yet, then `exec` (replace itself with) the real `mvn` and pass on every argument. You never edit it; it is generated by `mvn wrapper:wrapper -Dmaven=3.9.16`.

`mvnw.cmd` is the same job for Windows `cmd.exe`. Nothing in this repository uses it, but it is part of the standard wrapper and keeps the project buildable on Windows.

## 6. Try it yourself

- `./mvnw -v`. Expected: `Apache Maven 3.9.16`, then the Java version `25.0.x`.
- `cat .mvn/wrapper/maven-wrapper.properties`. Expected: the three lines shown above.
- `ls ~/.m2/wrapper/dists/apache-maven-3.9.16/`. Expected: one folder with a hash name, holding the unpacked Maven.
- `ls -l mvnw`. Expected: a line starting `-rwx`, so it is executable.

## 7. Mistakes people make

- Running plain `mvn` instead of `./mvnw`. That uses whatever Maven is installed, maybe a different version.
- A Docker image without `curl` or `wget`. The `eclipse-temurin` JDK image has neither, so the `only-script` wrapper falls back to compiling a Java downloader, which is very slow on a starved machine; the Dockerfile here installs `curl` first.
- Committing `target/` or `~/.m2`. Only the wrapper files are committed.
- Forgetting that the first build needs the network.

## 8. Check yourself

1. Why does the repository contain `mvnw`?
   **Answer:** So the build runs with the pinned Maven 3.9.16 on any machine, without installing Maven.
2. What does `distributionType=only-script` mean?
   **Answer:** Only the shell script is checked in; there is no wrapper jar. The script downloads Maven itself.
3. What are the `--add-exports` lines in `.mvn/jvm.config` for?
   **Answer:** They let the code formatter reach the JDK compiler's internal parser, which Java 25 hides by default.
4. Where is Maven stored after the first run?
   **Answer:** In `~/.m2/wrapper/dists/`.
5. What command prints the Maven version used?
   **Answer:** `./mvnw -v`.
